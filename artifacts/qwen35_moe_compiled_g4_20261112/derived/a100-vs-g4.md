# A100과 G4 compiled parallel MTP 비교

기존 A100-SXM4-80GB 2026-11-09 실행과 G4 RTX PRO 6000 Blackwell Server Edition 2026-11-12 실행을 비교했다.
같은 checkpoint revision, 5개 입력 ID, batch 1, cache 2048, 256 output tokens, warmup 3, repeats 5,
PyTorch 2.11.0+cu130/Triton 3.6.0/FLA 0.6.0, parallel verification, compile+CUDA Graph 조건이다.
모든 네 모드에서 CUDA Graph launch를 관측했다. 별도 세션의 historical 결과이며 현재 HEAD로 A100을 다시 실행하지 않았다.

## 시간

각 칸은 **A100 → G4**, ms/token, 5회 중앙값. `†`는 해당 GPU의 MTP-off와 5회 모두 출력이 달랐음을 뜻한다.

| 프롬프트 | off | k=1 | k=2 | k=3 |
| --- | ---: | ---: | ---: | ---: |
| chat_long | 5.5534 → 4.6488 | 5.8750† → 4.1505† | 5.0664† → 3.7890† | 4.8925† → 3.5182† |
| code_1k | 5.5386 → 4.6190 | 5.3982† → 3.9930 | 4.5731† → 3.4206 | 4.5258 → 3.2078 |
| prose_1k | 5.5531 → 4.5625 | 5.5531† → 4.1976† | 5.0899† → 3.6560† | 3.8331† → 2.8154† |
| math | 5.5575 → 4.5494 | 5.5776 → 4.0097 | 4.5268 → 3.3302 | 4.1480 → 2.8848† |
| korean | 5.4513 → 4.5445 | 6.4205† → 4.3189† | 5.8693† → 4.4853† | 6.2956† → 4.8707† |

MTP-off의 G4 시간은 A100의 0.8186~0.8371배, 즉 약 16.3~18.1% 짧았다.
그러나 GPU 간 baseline 출력까지 같은 프롬프트는 채팅과 수학뿐이었다.

## 출력까지 같은 비교

수학 off/k=1/k=2는 두 GPU의 모든 반복에서 256 generated IDs가 같고 각 GPU의 MTP-off와도 같다.
이 조건에서 A100/G4 시간 비율은 off 1.2216배, k=1 1.3910배, k=2 1.3593배다.
코드 k=3은 양쪽 모두 자기 baseline과 일치하지만 GPU 간 출력이 달라, 4.5258/3.2078을 동일 출력 workload의 speedup으로 단정하지 않는다.
수학 k=3은 A100에서는 일치했으나 G4에서는 token 18부터 달라졌으므로 직접적인 출력 보존 속도 비교에서 제외한다.

| 프롬프트 | GPU 간 off 출력 동일 | 최초 차이 생성 토큰(1-based) |
| --- | --- | ---: |
| chat_long | 예 | — |
| code_1k | 아니오 | 220 |
| prose_1k | 아니오 | 175 |
| math | 예 | — |
| korean | 아니오 | 86 |

## 라운드 비용

수학 k=2는 A100 12.7348 ms/round, G4 9.4725 ms/round였다.
수락량은 각각 2.8132/2.8444 tokens/round로 비슷하다. 이 사례의 시간 차이는 수락량 증가보다 round 자체가 짧아진 영향이 크다.
각 GPU에서 자기 off 대비 출력 보존 가속은 A100 수학 k=3 1.34배·코드 k=3 1.22배,
G4 수학 k=2 1.37배·코드 k=3 1.44배다. 코드의 GPU 간 출력은 서로 다르다.

## 하드웨어 하한과 비교

A100 80GB SXM은 명목 HBM bandwidth 2039 GB/s, G4 Server Edition은 GDDR7 1597 GB/s다.
[A100 NVIDIA 자료](https://developer.nvidia.com/blog/supercharging-worlds-fastest-ai-supercomputing-platform-on-hgx-a100-80gb-gpus/),
[G4 NVIDIA 사양](https://www.nvidia.com/en-us/data-center/rtx-pro-6000-blackwell-server-edition/).

| 코드 조건 | A100 이상적 streaming | G4 이상적 streaming | A100 실측 | G4 실측 |
| --- | ---: | ---: | ---: | ---: |
| plain | 1.8005 | 2.2988 | 5.5386 | 4.6190 |
| mtp1 | 1.2222–1.4812 | 1.5726–1.9058 | 5.3982 | 3.9930 |
| mtp2 | 1.0624–1.4278 | 1.3660–1.8358 | 4.5731 | 3.4206 |
| mtp3 | 1.0545–1.5122 | 1.3359–1.9158 | 4.5258 | 3.2078 |

위 표는 G4 분석의 같은 logical-byte 시나리오에 각 GPU bandwidth와 실제 emitted/round를 적용한 참고값이다.
실제 DRAM bytes/cache hit/route overlap은 측정하지 않았다. 하한 모델은 A100 쪽이 더 낮지만 실측은 G4 쪽이 짧다.
따라서 이 구현의 관측 차이를 peak bandwidth만으로 설명할 수 없다. 현재 selected-expert는 FP32 SIMT 산술이며,
실제 차이에는 커널의 instruction/occupancy/cache 효율, GPU별 autotune과 host synchronization 등이 관여할 수 있으나 원인별 비중은 미측정이다.

## 소스·clock 차이

두 실행 archive의 `speculative.py`, `qwen3_5.py`, `quant_kernels.py`, benchmark 파일은 byte-identical이다.
활성 expert `_project`와 `_combine`도 AST가 같다. G4 archive에는 A100 전용 packed branch가 추가됐지만 G4에서는 선택되지 않는다.
따라서 이 G4 실측을 현재 packed kernel을 사용한 A100 재측정과 비교한 것으로 해석하면 안 된다.
양쪽 모두 provider 기본/자동 clock이며, 동일한 fixed-clock 실험이 아니다. A100 400W, G4 600W power limit이 기록됐다.
A100 원실행에는 지속 clock telemetry가 없고 G4에는 1초 telemetry가 있으므로 같은 clock 유지 여부는 확인할 수 없다.
